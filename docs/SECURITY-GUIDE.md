# امنیت

- رمزها با PBKDF2 (۱۰۰هزار تکرار) و salt تصادفی هش می‌شوند؛ نشست‌ها با توکن تصادفی و انقضا.
- نقش‌ها و مجوزها در سرور بررسی می‌شود (نه فقط رابط). ویراستار به بخش‌های مدیریتی و مالی دسترسی ندارد.
- ورودی‌ها در سرور اعتبارسنجی می‌شود؛ پرس‌وجوها پارامتری‌اند؛ خروجی HTML در فرانت‌اند با DOM امن ساخته می‌شود.
- CORS فقط برای `ALLOWED_ORIGINS`؛ هدرهای nosniff، X-Frame-Options و Referrer-Policy روی پاسخ‌های API. (CSP روی سایت ایستا: GitHub Pages امکان تنظیم هدر نمی‌دهد؛ اگر لازم داری، پشت Cloudflare Pages/CDN با هدر سفارشی منتشر کن.)
- محدودیت نرخ: عمومی ۳۰۰ درخواست در دقیقه برای هر IP، سخت‌گیرانه‌تر برای ورود (هم IP هم ایمیل)، ثبت‌نام، تغییر رمز، هوش مصنوعی و ساخت درخواست.
- بازیابی رمز فراموش‌شده خودکار (ایمیلی) نیست؛ مدیر از «کاربران ← پرونده» رمز جدید تعیین می‌کند.
- `SETUP_KEY` فقط برای راه‌اندازی است؛ پس از ساخت مدیر مسیر راه‌اندازی بسته می‌شود، ولی بهتر است Secret را حذف کنی.
- کلید هوش مصنوعی فقط در Secret سرور است و هرگز به مرورگر نمی‌رسد؛ خرابی سرویس هوش مصنوعی سایت را از کار نمی‌اندازد.
- داده‌ی کاربران زیر ۱۸ سال: رضایت والد و محدودیت شیوه‌ی ارتباط.

## توصیه‌ها
- مدیر با رمز طولانی و یکتا؛ تعداد مدیران را کم نگه دار.
- به‌صورت دوره‌ای از دیتابیس خروجی بگیر (`wrangler d1 export masir-man-db --remote --output backup.sql`).
- `audit_logs` را در پنل مرور کن.
- قبل از انتشار عمومی، مشاور و بنر نمونه را حذف یا با واقعی جایگزین کن.
- درباره‌ی الزامات قانونی نگهداری داده‌ی شخصی و پذیرش پرداخت، با متخصص حقوقی مشورت کن؛ این پروژه مشاوره‌ی حقوقی نیست.
